######## 4 the error path, and what it does NOT cover ########
rejected payloads in ingestion_errors : 0
None in this window, which means no payload failed to parse.

The finding of this check is the boundary, not the count. Ingestion has two ways to discard a message and only one of them leaves a trace.
  parse or write failure   -> ingestion_errors, raw payload retained
  device not commissioned  -> dropped, INFO log line only, no row
The second path returns success from the handler (mqtt.rs, the gate before parsing), so traffic from an unknown device leaves no persistent record. Verified by running the generator with --rogue, which published from uncommissioned devices and produced no rows here. For provenance that is defensible, since nothing was stored and nothing needs an origin. For operations it is a blind spot, because a misconfigured real device disappears without anything an operator can query later.

Where the payload carries no device clock, ingestion stamps the receive time into both fields. All four provenance fields are then present, but the measurement time adds nothing over the receive time. This is a property of the device protocol, not of the platform, and it is reported rather than averaged away.
